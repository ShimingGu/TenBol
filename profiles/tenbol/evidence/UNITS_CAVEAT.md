# 重要：转移动率 q 的单位未定论，历史对比数字不可靠

## 事实

`reference_run` 返回的 `transfer_q` 上限是 **20.14**，而同一批数据里 P(k) 的 `kh`
网格上限是 **20.0**。`kh` 的单位可以确定是 h/Mpc（`sigma8` 用它算出 0.809973，与
CAMB 的 0.809976 差 3e-6）。

如果 `transfer_q` 也是 h/Mpc，那么历史上的对比脚本里写的

```python
q = np.asarray(ref["transfer_q"]) / 0.67
... np.interp(np.log(kh), np.log(q), d)
```

实际上是在 **k = kh·0.67** 处采样 CAMB，而不是 kh。反过来的写法
（`np.interp(np.log(kh*0.67), np.log(q), d)`，`q = transfer_q/0.67`）等价于在
**k = kh·0.449** 处采样。

我在本会话的不同脚本里**两种写法都用过**，所以此前报告的所有
"δ/δ_CAMB = 0.99x"、"偏差 1.7%"、"偏差 9.1%" 等数字，其 k 对应关系并不可靠。

## 用统一、自洽的单位（`q` 直接当 h/Mpc，在 `log(kh)` 处插值）重测

| k [h/Mpc] | 我们的增长比 | CAMB | 比值 | 偏差 |
|---|---|---|---|---|
| 0.0010 | 1171.03 | 1162.14 | 1.0077 | +0.77% |
| 0.0020 | 1147.22 | 1125.01 | 1.0197 | +1.97% |
| 0.0042 | 1128.60 | 1047.42 | 1.0775 | +7.75% |
| 0.0086 | 1037.82 | 923.78 | 1.1234 | +12.34% |
| 0.0175 | 907.47 | 774.83 | 1.1712 | **+17.12%** |
| 0.0358 | 761.79 | 687.30 | 1.1084 | +10.84% |
| 0.0733 | 729.85 | 650.32 | 1.1223 | +12.23% |
| 0.1500 | 704.39 | 649.67 | 1.0842 | +8.42% |

即：在自洽单位下，最大偏差是 **17%**（k ≈ 0.0175 h/Mpc），不是一个可以忽略的数字。

## 这说明什么

增长比 δ(0)/δ(1000) 在纯物质主导下应与 k 无关。CAMB 的该量从 k=0.001 的 1162
降到 k=0.0175 的 775，是辐射时代进入视界造成的 Meszaros 压制；我们从 1171 只降到
907，即**我们的辐射时代压制不足**。问题出在 z ≳ 1000 的演化，与 z < 1000 无关。

## 待办

1. 先用 CAMB 的 `Transfer.hubble_units` 或 `get_matter_power_spectrum` 的 k 网格
   交叉验证 `transfer_q` 的单位，确定后再谈任何精度数字。
2. 修正辐射时代的演化（初值、光子/中微子层级、Meszaros 相位的处理）。
3. 在此之前，`Tenbol_handout.md` 与 `Tenbol_progress.md` 里的精度表述都需要加注。

## 追加（同一会话）：两个修正

### 1. `transfer_q` 的单位已经确定是 h/Mpc

用 `Transfer.kmax = 5.0` 和 `12.0` 各跑一次：

```
Transfer.kmax= 5.0 -> transfer_q max = 5.2500   P(k) kh max = 5.0000   ratio = 1.05
Transfer.kmax=12.0 -> transfer_q max =12.6000   P(k) kh max =12.0000   ratio = 1.05
```

比值恒为 1.05（CAMB 内部网格的 padding），说明 `transfer_q` 与 `kh` **同单位**，
都是 h/Mpc。因此 `q = transfer_q/0.67` 是错的，等价于在 `k = 0.67·kh` 处采样。

### 2. 上表的 "+17%" 很可能是除零放大的假象

那张表用的是 `δ(0)/δ(1000)`。在 k ≈ 0.0175 h/Mpc 附近，δ(k, z=1000) 正处于
重子声学振荡的过零区，除以一个接近零的量会把任何微小的相位差放大成巨大的比值。
所以 17% 这个数字**不能**直接当作精度指标。

### 3. 真正的硬缺陷：k = 1 h/Mpc 数值发散

用 z=0 直接比形状时，k=1.0 h/Mpc 处我们的 δ 达到 **2.5e148**，即求解器在高 k
发散。这一条与精度讨论无关，是必须先修的稳定性问题。

## 结论

在 (a) 单位约定统一、(b) 过零区排除、(c) 高 k 发散修掉 之前，本仓库里任何一个
"对 CAMB 的 x%"数字都不应被引用。

另外，逐块追踪 k = 1 h/Mpc 的演化状态时，`Fg`、`G`、`Fnu` 三个块的

对比：同一条代码路径在 k = 0.15 h/Mpc、从正确的 `a_start=1e-7` 起步时，
`max|Fg l>=3|` 能到 8.6e-3（非零）。所以差别在 k 上，不在起步点。

两个待查项，都不需要再猜：

1. 为什么 k = 1 h/Mpc 时 clamp 为 False 却仍有 `dY[fg(3)] == dY[pig] == 0`。
   可疑点：`pig_dot` 里 `k*2/5*qg_e` 项若 `qg_e` 为 0 且 `pig`、`g(2)`、`fg(3)`

   若成立，说明 `initial_state` 对 l >= 2 的初值全给 0，而 RH​S 在 l = 2 处
   也没有独立源，导致永久零解。
2. k = 1 h/Mpc 的发散是在 (1) 之上的另一层问题。

修复顺序：先让 `pig`（光子四极矩）在 l = 2 处有正确的源，再谈高 k 稳定性。

## 追加：一个无法用现有解释说明的硬矛盾

在 a = 1e-2 处同时打印状态和 rhs：

```
k=0.15 h/Mpc: kappa=1.06e-06 tau_rem=12827 k*tau_rem=1289.1
              tcu=False rsa_g=False
              pig=-5.93e-02  qg=2.33e+00  dY[pig]=0.0e+00  dY[fg(3)]=0.0e+00

k=1.00 h/Mpc: kappa=1.06e-06 tau_rem=12827 k*tau_rem=8594.3
              tcu=False rsa_g=False
              pig= 0.00e+00  qg=2.96e+00  dY[pig]=0.0e+00  dY[fg(3)]=0.0e+00
```

两个 k 上 `tcu` 和 `rsa_g` **都是 False**，所以 `np.where(tcu | rsa_g, 0.0, pig_dot)`
不应该把导数置零。而 `pig_dot` 的第一项 `k*(2/5)*qg_e` 用打印出来的
qg ≈ 2.3–3.0 计算，k = 0.1–0.67 /Mpc，应给出 0.05–0.79 的量级，**不是 0**。

结论：`dY[L.scalar("pig")]` 在打印时刻确实为 0，但它与同一函数里打印出来的
qg、kappa、tcu、rsa_g 不相容。这不是"初值为零所以永远为零"能解释的——
qg 非零就意味着 l = 2 有源。

排查方向（下次从这里开始，不要再猜）：

1. 在 `rhs` 内部、`dY[L.scalar("pig")] = ...` 这一行的**紧前一行**插入
   局部打印，确认函数内部的 `tcu`、`rsa_g`、`qg_e`、`pig_dot` 与外部看到的是否一致。
   外部算的 mask 与内部用的 mask 若不相等，就是 `coefficients(a)` 两次调用之间
   状态不一致（例如 `_tau_rem` 的缓存）。
2. 核对 `L.fg(2) == 9`（etak 行）这件事是否也在 `dY` 侧造成越界写：`fg(2)` 应为
   pig（行 5），当前实现返回 9，所以 `dY[L.fg(2)]` 若被写会覆盖 etak。
3. 只有在 (1)(2) 都确认无误之后，才去讨论 k = 1 h/Mpc 的 2.5e148 发散。

## 更正：光子层级的"冻结"是正确行为，不是缺陷

上一节说 `Fg/G/Fnu` 恒为零是缺陷，**这个判断是错的**，记录如下以免重蹈。

### 证据

`rhs` 内部打印（a = 1e-2，k = 0.15 h/Mpc）：

```
DBG pig: tcu=[False] rsa_g=[True] qg_e=[4.63] pig=[-0.0593]
         polter=[-0.0318] kappa=[1.06e-06] sigma=[-3.476]
         pig_dot=[0.00052667]
dY[pig] = 0.0
```

即 `rsa_g` 在函数内部是 True，`np.where(tcu | rsa_g, 0.0, pig_dot)` 把导数清零。
冻结确实在发生，且由 RSA 判据触发。

### 为什么这样是对的

试把光子 RSA 判据改成"用剩余共形时间"（`rsa_g = k*tau_rem < rsa_ktau`，
与 `inv_tau = 1/tau_rem` 保持一致），结果：

```
FAIL NumericalFailure non-finite perturbation state at a=2.429e-03, k=6.700e-01
```

在 a = 2.4e-3、k = 0.67 /Mpc 处，`k*tau_rem ≈ 9500`。要解析这个层级需要
lmax ~ 9500 阶，而 `lmax_g = 24`，必然发散。

也就是说：**累积形式 `ktau = k*tau` 的 RSA 判据，正是让光子层级在解耦后及时
冻结、从而把 lmax 压在 24 阶的机制**。换成剩余形式就把这个保护拿掉了。

### 后续若要提高高 k 精度，正确方向是

让 `lmax_g` 随 `k*tau_rem` 增长（CAMB 的 `lmaxg` 就是这么做的），而不是
放开 RSA 而保持 lmax 不变。这需要在 `StateLayout` 上引入按 k 分桶的可变
lmax —— 与本项目"dense Y[D,T]、Y 形状批不变"的既有约束冲突，属于架构级改动，
应单独立项。
